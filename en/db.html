Memo Explanations

A simplified explanation of everything covered in the memo's Databases section — matched item by item against the official material.

01. Concepts — From Data to Information

Data is raw material; once processed (for example by merging several fields together), it becomes Information — this equation is asked in every exam.

🗄️ Analogy: a database is a smart filing cabinet: each table is a drawer, each record a file inside the drawer, and each field a slot in the file. And the "archivist" who decides who opens what is the database administrator, the DBA.
⚙️

Database Management Systems

DBMS programs store, update and retrieve data — the best known: Oracle, SQL Server and Access. Arithmetic or logical operations can be performed on the stored numeric values.

🪟

The Main Window

The database's main window consists of 3 sections. Access ships with a default database called Blank Database, and to create a ready-made store database: Templates.

👨‍💼

Database Administrator DBA

Responsible for controlling all permissions and uses of the database.

🕵️

System Analyst System Analyst

Analyzes the requirements of the entity that will use the system, identifies all the data and develops the specifications. ⚠️ Attributing this task to the "application programmer" is a recurring trap!

02. Tables & Fields — Numbers to Memorize

This part's questions are numbers and locations: 64 characters, 200 default size, one field for the key:

🔑

Primary Key Primary Key

The field that distinguishes records from each other. It consists of one field only, non-duplicate, and is preferably numeric — it can be replaced by a substitute field (an Alternative Key).

📏

Limits to Memorize

A field name must not exceed 64 characters (not 67!). And the default size of a text field is set to 200 from the Options command — not "Account".

✳️

The Required Property Required

When set to Yes, a value must be entered in the field — the record cannot be left blank.

🧱

Creating and Formatting Tables

A new table from the Create tab · table data formatting from the Home tab · saving the database under a new name with the Save As command on the File tab.

03. Relationships — The Heart of the Database

There is no single isolated table in a real database — tables connect through three types of relationships:

1️⃣

One to One 1:1

One record matches exactly one record — like a citizen and their national ID number.

🔢

One to Many 1:M

One record matches several records — like one department and its many students.

🔀

Many to Many M:N

Like a student and academic subjects: a student takes more than one subject, and a subject is taken by more than one student — this relationship needs an Intermediate Table (such as the Delivery table).

🔗

How Are Tables Linked?

Through the Foreign field in one table and the Primary field in the other, provided they hold the same value — the shared field must be of the same type, with matching data type and size at creation. Relationships are created from the Database Tools tab.

🛡️

Referential Integrity

Referential Integrity: requiring that the primary-key data in the primary table exists in the foreign-key field of the secondary table — so no "orphan" records appear.

🧹

Normalization Normalization

Rules that ensure the removal/scarcity of duplicated data — not "the accuracy of repeated data" (trap!). Its degrees range from 1NF to 5NF, and reaching 3NF is sufficient for most applications.

🎓 The student-and-results question: the memo considers the statement "the student's relationship with academic results is one-to-many" wrong, favoring many-to-many if the results are a consolidated grade report — while admitting this is the memo author's personal view. Memorize the certainty: student and academic subjects = many to many.

05. Forms & Reports — The Input Interface and the Print Interface

A Form is the gateway for entering data, and a Report is the object for displaying and printing it:

📋

The Form Form

Used to enter data and display one record at a time — not all records at once (trap!). And Form View is the view that displays the actual data.

🧙

The Form Wizard Form Wizard

For creating a form that includes fields from several linked tables in the same database — the "Split Form" is something else (trap!). And the field list must appear when creating from a table.

🖼️

Form Background

To add one: Format → Picture → choose the appropriate background → OK. To resize it to fit the space: the Property Sheet, then choose "Form" from the details list.

📄

Reports Reports

Objects for displaying and printing data. They are created from the Create menu first (not "Design then Create"!) · a report is viewed after naming it · its layout can be set to "Detailed" · and its data can be updated before printing if new data was added.

📤

Import and Export

Both from the External Data tab. You can export as text and open it in Word, and edit reports after exporting to TXT with a word processor — and export steps can be saved (the trap says the opposite!).

🧭

Navigation Pane and Info

The Navigation Pane matters for easing report printing and getting a copy of the database's data. The Info command shows database information: the number of tables, queries and forms (not "cells"!). Compact and Repair is on the Database Tools tab.

07. What the Memo Doesn't Cover

The official material (98 pages) adds entire topics with no memo questions:

👥

The Database Team — 8 Roles

The material lists 8 roles on the team, most notably: the database administrator (DBA), the system analyst, the database designer, the application programmer, and the end user.

🔍

The Query Grid QBE

Query By Example: the lower grid in query design where fields and Criteria are set — "query by example" instead of writing SQL commands by hand.

🔃

Report Wizard Sorting

The Report Wizard allows sorting by up to 4 fields — ascending or descending.

📗

The Preferred Export

The material presents exporting to Excel as the first destination for exchanging table data, alongside other formats. ⚠️ The TXT text export mentioned in the memo is not stated explicitly in the official edition.

🧩

The Split Form Split Form

Creates two synchronized views of the same data: a form + a datasheet — which is not the "Form Wizard", the tool that gathers fields from several linked tables.

📐

The Five Normalization Degrees

From 1NF to 5NF — each degree removes a kind of duplication, and reaching 3NF is sufficient for most practical applications.

⚖️

Info or Tools? (A Reconciling Note)

The official book also attributes Compact & Repair and encryption to the Info menu on the File tab, while the memo goes with the Database Tools tab — both appear in the material's text ⚠️: the Info command shows the information and holds the compact button, and the Database Tools tab has the same command plus the "Analysis" group.

🎓

An Internal-Contradiction Alert

The student/subjects example appears in the official book with two conflicting wordings on two consecutive pages (p.59 vs p.60) — the accepted correct reading: many to many M:N via an intermediate table.
